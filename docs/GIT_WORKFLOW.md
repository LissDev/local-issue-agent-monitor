# Git workflow

Для каждой задачи создавайте отдельный GitHub Issue, ветку и worktree.

Формат имени ветки: `<type>/issue-<number>/<short-name>` (например,
`feat/issue-42/issue-monitor`).

Коммит создаётся только когда его явно запросили. `git push` никогда не
выполняется без отдельного явного запроса.

## Очистка после успешной интеграции

Очисткой артефактов задачи управляет интегратор, а не агент в worktree. После
того как PR успешно влит и связанный Issue закрыт, интегратор обязан удалить
ставшие ненужными локальные worktree и локальные ветки этой задачи.

Перед удалением интегратор подтверждает, что PR влит, Issue закрыт, процесс
агента завершён, а worktree чистый. Нельзя удалять worktree или ветку для
`running`, `needs-human`, `failed` либо незакоммиченной работы: их сохраняют
для восстановления и разбирают отдельно. При squash-слиянии проверять нужно
статус PR и Issue, а не только достижимость исходного коммита из `main`.

Агент не удаляет собственный worktree, ветку, JSONL-лог или runner-файл. После
подтверждённой интеграции это делает интегратор через `git worktree remove` и
`git branch -d`; удаление удалённой ветки выполняется только если оно отдельно
разрешено политикой репозитория.
